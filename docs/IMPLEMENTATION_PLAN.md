# AI Investment Engine 落地方案（v0.2 → v1.0）

基线时间：2026-11-05（北京时间）。v0.2 已增加 AKShare 日线接入、本地缓存、证据分类和基础历史回测；OTW 仍保持 MCP 只读。

## 0. 系统定位

**OTW（权威数据和记录层）**：真实/参考行情、持仓、模拟交易、投资研究、全局策略文档、历史分析、绩效。保持现有账本结构。

**Investment Engine（新增独立 Python 服务）**：拉取 OTW 数据 → 证据质量审核 → 投资假设变更判别 → 策略诊断/回测 → AI 提出可解释建议 → 独立风险否决 → 输出可追溯报告 → 由 OTW 模拟交易接口在受控条件下执行。

**调度**：先沿用现有北京时间 09:00/11:00/14:00/17:00 任务，暂不迁移。将来 OTW/平台调度器作为唯一调度源，避免两个系统重复跑分析和生成订单。交易日和时区以 Asia/Shanghai 明确处理。

**明确非目标**：不做真实证券交易，不引入外部券商下单，不保证收益，不用虚构数据替代实时查询，不直接把股票代码丢给 LLM 获取“买卖推荐”。

## 3. 每次决策的状态机（v0.1）

1. `DATA_LOADED`：读取 OTW context 和全局文档（失败则失败关闭）。
2. `EVIDENCE_REVIEWED`：四项证据分别是 supporting、contradicting、unknown，来源时间超过 as_of 的一律不采纳。
3. `QUANT_DIAGNOSTIC`：有合法历史行情才计算简单均线；当前只是诊断，不是可交易回测。
4. `PROPOSAL`：可能产生 buy_candidate、sell_candidate、hold、no_trade。
5. `RISK_VETO`：v0.1 对所有买卖候选一律拒绝，并记录数据/风控理由。
6. `DECISION`：输出 `no_trade` 或 `hold`；不产生 OTW 模拟成交。
7. `AUDIT_EXPORTED`：本地 JSON 包含证据、策略、数据状态、风险、决策、OTW `/runs` 预览。

注：第三方人工标注 `reviewed_by_human=true` **不等于**已完成独立来源校验。未来需要接入可信数据抓取与证据复核服务。绝不能据此自动下单。

## 4. 优先级与最小成功标准

下一轮优先级：

1. **P0**：用户部署环境实际 OTW GET 成功，验证账户/文档和 token 权限；失败时不伪造结果。
2. **P0**：下载并标准化真实历史日线，补齐时间戳、数据来源和历史缺口。
3. **P1**：可重复执行的基准回测，实际交易成本与市场规则可复核。
4. **P1**：同一个策略、同一时刻重复请求，不造成重复 OTW 记录。
5. **P2**：TradingAgents / 其他 AI 作为可替换研究插件，并评估相对纯规则策略的增量价值。

**阶段 A 验收**：本地 fixture 与真实只读 OTW 均能生成结构化报告；缺历史/缺证据时明确降级；不改变现有 OTW 账户、订单、研究文档或定时任务；完整测试通过。

**阶段 D 验收**：完成明确的恢复授权、后端风控、幂等重试与模拟成交对账，才能称为“模拟交易闭环已打通”。
